# 08 · 浏览器执行 API

PRD 1.0 · 2026-10-18 · 付费计算服务 · 第一批候选  
状态：设计提案，未实现/未付款/未提交。先读[总体接入设计](../总体接入设计.md)与[接口事件约定](../接口与事件约定.md)。

## 1. 用户与真实场景

**用户：**需要读取动态网页、获取截图或执行有限页面步骤的 Agent 开发者。

**第一次使用：**产品研究 Agent 要提取一个公开网站的产品价格和页面截图，购买一次浏览器执行，取得真实渲染后的结构化结果及证据。

**问题：**普通 HTTP 抓取不能执行页面脚本；本地浏览器环境不稳定。服务需要控制运行资源、明确执行范围并保证结果可取。

**Kite 接入价值：**出售真实浏览器算力与产物，Kite 是 Agent 采购服务的发现/授权/付款通道。首版不做“AI 自由操作一切网页”，避免失控执行和无法确定交付。

## 2. MVP 范围

**P0，首版必须完成：**

- 固定三个动作：render、screenshot、extract；只读公开或明确获准页面，最多一次导航和限定选择器。
- 每次运行固定浏览器/视口/时区，限制时间、内存、请求数和输出大小，报价按明确规格而非不可预测 token。
- 返回截图、提取字段、执行环境、目标 URL 与实际完成状态。
- 隔离浏览器、验证所有导航与网络目的地，产物只给真实买方；首版同步有界任务。

**P1，有真实反馈后再做：**

- 复用付费长任务组件支持有限多步任务；有真实用户后再做更复杂操作。
- 提供可运行的 Agent 调用示例和已有宿主适配，而非另做聊天应用。

**首版排除：**不提供任意代码执行、不代用户登录第三方、不绕验证码、不把模型猜测当网页观测。

## 3. 完整用户流程

1. 用户选定 action、URL、视口与提取选择器，服务预检规格并给固定报价。
2. Passport 发现/预检服务，获批后通过 execute 提交 JSON。
3. 卖方验证付款，启动隔离浏览器并执行固定操作。
4. 实际结果通过规格校验，保存产物与请求关联。
5. 结算后返回 JSON 和受限取件路径；同一 operation 恢复已完成结果。
6. 目标站限制或执行失败时返回明确业务错误，不返回猜测数据。

## 4. Kite 能力接入

| 官方能力 | 接入方式 | 保存与验证 |
|---|---|---|
| 买方 | ksearch、delegation、session execute | 从真实 example_request 起调用，不猜参数 |
| 卖方 | x402 402/verify/settle | 同步任务成功后结算；网络和资产先过 G0 |
| 登记 | service.yaml/source=custom | 真实 HTTPS base_url、合法 schema、每端点实跑示例 |

**接入前置：**所有涉及真实付款的路径先完成 G0，固定 network/asset/facilitator/CLI/账户环境；见总体接入设计。真实身份或 Runtime 不可得时明确 blocked，不能用 mock 替代。

**授权边界：**应用与业务权限自己验证；Passport 的 passkey 批准保留给真实用户；本轮 PRD 编制不发起任何授权或支付。协议实例、金额、会话和示例均以现场预检与实际输出为准。

## 5. 接口与数据

**拟提供接口：**POST /v1/browser/run；输入 {operation_id,url,action,viewport,selectors?}；输出 {run_id,status,final_url,environment,fields?,artifacts,observed_at}。GET /artifacts/{id} 为购买后鉴权读取；不把带付款中间件的整个 /v1/* 当作免费取件区。

**核心对象：**BrowserSpec、QuoteVersion、Run、NetworkDecision、PageObservation、Artifact、Purchase、RetrievalGrant。

operation_id、付款证据、业务版本及产物按公共事件契约关联。接口/包名属于本项目设计，不代表官方已经发布同名能力。

## 6. 状态与恢复

PRECHECKED → PAYMENT_VERIFIED → RUNNING → RESULT_READY → SETTLED → DELIVERED；失败细分 blocked_target、navigation_error、resource_limit、payment_unknown。

- 校验 DNS、IP、所有重定向和子请求，阻止内网/云元数据；浏览器运行在无宿主凭证的隔离环境。
- 验证码、登录和站点禁止访问返回 blocked，不自动绕过；不执行下单、消息、删除和转账。
- 截图可能含隐私，产物受权访问且按约定期限删除；异常日志不保存 cookies/headers。

任何付款未知均不能通过换 key 自动重买；任何产物恢复都需要原权限。测试桩中的假付款不产生真实交付承诺。

## 7. 开发任务拆分

- 08-T01：验证一类真实买方需求，固定三动作与资源规格。
- 08-T02：实现隔离执行器、网络控制和产物管理。
- 08-T03：实现计费包装、操作幂等和错误分类。
- 08-T04：完成 G0、真实试单与失败测试。
- 08-T05：找两个实际 Agent 集成者试用并修正协议。

**投入粗估：**5–7 人周。先做 M0 兼容与样本验证，再做独立核心、真实互通及发布；外部批准、环境开通和审核不计入可承诺工期。

## 8. 界面与使用体验

API 文档和一个请求调试台，旁边展示实际截图、字段和执行记录；不做花哨浏览器模拟界面。

在需要用户决定时展示价格、范围、权限和失败状态；普通产品页面不堆协议实现细节，技术证据留在诊断/报告页。

## 9. 验收与演示

下面是目标，尚未运行或达成。

- B01：自建动态页面中的字段与截图真实产生，可用固定环境复现。
- B02：私网地址、DNS/重定向逃逸、越权产物和资源滥用测试被拦。
- B03：导航失败与目标不允许访问不伪造成功数据；合格同步结果生成后才结算。
- B04：一次真实 Passport 购买可关联截图/提取结果与付款证据，manifest 示例可重跑。

**完整演示：**Agent 购买一个动态测试页面的渲染，取得截图和价格字段；再请求私网与坏选择器，展示拒绝和未提前结算。

**试用观察：**有效执行成功率、真实单次资源成本、用户重试原因、产物可取率和重复调用。

## 10. 提交与独立性

x402 付费服务方向较直接，需合法使用目标、公开 HTTPS、清单和真实调用。目录收录仍待外部审核。

项目核心包括本 PRD 定义的模型、业务引擎/状态/断言与样本；支付和基础依赖可正常共享，不复制其他参赛实现换名。EC 映射、活动审核与真实贡献是否被统计分别跟踪，不用本 PRD 保证收录。
